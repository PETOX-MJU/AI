# 숏폼 화면 분류기

스크린샷 한 장을 받아 "지금 숏폼을 보고 있는가"를 판별하는 온디바이스 분류기.
MobileNetV3-Small 전이학습 → TFLite. 산출물은 FE 앱에 번들된다.

## 왜 VLM이 아닌가

이진 분류에 1.7B VLM은 과하다. CNN이면 5MB 미만·수십 ms·완전 오프라인이고,
무엇보다 **스크린샷이 기기 밖으로 나가지 않아** 개인정보 문제가 사라진다.

VLM 베이스라인은 `../experiments/shorts_detection/` 에 있다. 비교 대상으로 남겨 둔다.

## 순서

```
python prepare.py          # datasets/raw → datasets/split (train/val 분리)
python train.py            # 헤드 학습 + 백본 미세조정
python export_tflite.py    # int8 양자화 TFLite 변환
python eval.py             # 임계값 선택
```

## 데이터 수집 가이드

**최소 300장, 목표 500장.** 클래스 비율은 1:1 근처로.

`datasets/raw/shorts/` — 유튜브 Shorts, 인스타 Reels, 틱톡 피드 재생 화면

`datasets/raw/not_shorts/` — **여기가 중요하다.** 헷갈리는 화면을 일부러 많이 넣어라:
- 인스타 스토리 (세로 전체화면이지만 숏폼 아님)
- 유튜브 홈의 Shorts 썸네일 줄
- 세로로 찍은 일반 영상
- 유튜브 검색·댓글·프로필
- 카톡, 브라우저, 게임

여기서 틀리면 실제 앱에서도 틀린다. 쉬운 샘플만 모으면 검증 점수만 좋고 현장에서 무너진다.

## 판정 기준

**정밀도가 재현율보다 중요하다.** 숏폼을 가끔 놓치는 건 괜찮지만, 카톡 하는데 캐릭터가
튀어나오면 사용자는 앱을 지운다. `eval.py` 는 정밀도 90% 이상 중 재현율이 가장 높은
임계값을 추천한다.

- 정밀도 90% + 재현율 80% 이상 → 진행
- 정밀도 90%를 못 넘김 → 데이터 보강, 그래도 안 되면 앱 단위 감지(A안)로 후퇴

## 선행 조건

> ⚠️ **`FLAG_SECURE` 확인이 먼저다.** 유튜브·틱톡이 이 플래그를 걸어두면 화면 캡처가
> 검은 화면으로 나오고, 이 디렉터리 전체가 무의미해진다. 기본 화면 녹화로 30분이면 확인된다.

## 앱 연동 메모

- 입력: 224x224 RGB, 0-255 (모델에 전처리가 내장되어 있어 앱에서 정규화 불필요)
- 출력: 0~1 스칼라. 임계값 이상이면 숏폼
- 좌우 반전 증강은 넣지 않았다 — 숏폼 UI 버튼이 항상 오른쪽에 있는 게 핵심 단서라 반전시키면 단서가 깨진다
