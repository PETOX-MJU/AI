# FE(Android) 데이터 생산자 계약

AI 패키지는 **집계 이후의 산술과 경계**를 검증한다.
원시 Android 이벤트의 정확성은 검증하지 않으며 FE가 보장한다.

## 1. 출처

`UsageStatsManager`로 사용 기록을 조회한다. 디지털 웰빙의 화면을 읽는 것이 아니다.

- `PACKAGE_USAGE_STATS` 선언 후 `Settings.ACTION_USAGE_ACCESS_SETTINGS`에서 사용자가 직접 허용
- 상세 이벤트 보관은 제한적이다. 임의의 과거 전체 기록이 제공된다고 가정하지 않는다
- 날짜·야간 경계 판정은 `queryEvents()`로 정규화한 구간을 쓴다.
  `queryUsageStats()`의 집계 구간이 요청 범위와 정확히 일치한다고 가정해 잘라 쓰지 않는다
- OS 집계값을 참고 화면에 쓸 경우 `참고 통계`로 구분하고 이벤트 기반 판정에 섞지 않는다

## 2. 사용 구간 정규화

- 입력: Activity 전경/배경 전환, 화면 interactive 변화, keyguard 변화, 종료·부팅 이벤트
- 같은 앱의 여러 Activity 전환으로 **동일 시각을 중복 계산하지 않는다.** 앱별 구간 합집합을 쓴다
- **전경 + 화면 interactive + 잠금 해제** 구간만 사용량으로 센다
- 종료 이벤트가 없거나 시작 상태를 복원할 수 없으면 불확실성을 기록한다.
  새벽까지 사용했다고 임의로 연장하지 않는다
- 진행 중 구간은 조회 시점까지의 잠정값이며 확정 판정에 바로 쓰지 않는다
- 다른 앱의 구간은 앱별로 각각 집계한다. 멀티윈도우 때문에 **전체 앱 합계가 실제 경과 시간보다 클 수 있다**
- 자기 앱과 홈 런처·시스템 UI는 제외하고 제외 목록·판정 방식을 문서화한다.
  다른 일반 앱을 이름 추측으로 제외하지 않는다
- 백그라운드 오디오만 재생되는 시간은 전경 사용량에 포함하지 않는다

화면에는 `앱 사용 시간 합계`로 표시한다.
실제 수면 시간, 물리적 화면 켜짐 시간, 디지털 웰빙과 일치하는 수치라고 표현하지 않는다.

## 3. 품질 코드

각 집계는 `quality`와 `reason_codes`를 갖는다.

| quality | 조건 | apps |
|---|---|---|
| `complete` | 구간이 끝났고 시작 상태·조회 범위가 복원됐으며 미해결 공백이 없음 | 배열 (빈 배열 = 확인된 0) |
| `partial` | 일부만 확인됨 또는 진행 중 | 배열 (확인된 값) |
| `unavailable` | 권한 없음·조회 실패·보관 초과로 집계 불가 | **null** |

- `complete`는 OS 원본이 완전하다는 절대 보증이 아니라 **수집기의 확인 가능한 조건**을 만족한다는 뜻이다
- 허용 상태 한 번 확인이나 빈 이벤트 배열만으로 `complete, 0`을 만들지 않는다.
  조회 범위·수집 체크포인트·복원 가능한 상태가 함께 필요하다
- 재부팅·시간 변경·시간대 변경·장기 미실행 경계는 복구 여부를 판단하고,
  복구하지 못하면 공백으로 기록한다
- 같은 범위 재수집은 정규화 구간을 **교체/병합**하고 재집계한다. 누적 더하기로 중복 집계하지 않는다

AI 패키지는 `complete`이면서 `end_ms > as_of_ms`인 집계를 **거부한다.**
아직 끝나지 않은 구간에 complete를 붙이지 마라.

## 4. 구간 경계

AI가 프로필로 계산한 경계와 FE가 보낸 `start_ms`/`end_ms`는 같아야 한다.
`fixtures.json`으로 대조하라.

| kind | 범위 |
|---|---|
| `daily` | 로컬 자정 ~ 다음 로컬 자정 |
| `pre_bed` | `[취침 - 30분, 취침)` |
| `after_bed` | `[취침, 기상)` |

- `anchor_date`는 **밤을 시작하는 저녁이 속한 날짜**다
- 취침 입력이 12:00~23:59면 anchor_date 당일, 00:00~11:59면 다음 날
- 평일은 월~금 저녁, 주말은 토~일 저녁 일정을 쓴다
- 구간은 `[start, end)`다. 자정 이벤트를 두 날짜에 중복 포함하지 않는다
- **하루를 86,400,000ms로 가정하지 않는다.** DST 전환일은 23시간 또는 25시간이다
- DST의 존재하지 않는 로컬 시각은 전환 후 첫 유효 시각, 중복 시각은 먼저 오는 오프셋으로 해석한다

예: 일요일 저녁 목표가 `00:00 / 07:00`이면 구간은 일요일 23:30 ~ 월요일 07:00이고,
이 야간 미션은 **일요일(지난주)** 에 속한다.

## 5. 백그라운드와 패키지 이름

- `WorkManager`는 정확한 실행 시각을 보장하지 않는다.
  정시 수집·정시 월요일 알림을 약속하지 말고 다음 실행에서 갱신한다
- 강제 종료나 장기 미사용으로 회복 불가능한 기록은 **확인 불가**로 남긴다
- 앱 이름·아이콘 조회의 패키지 가시성은 사용 기록 권한과 별개다.
  필요한 `<queries>`를 좁게 선언하고 이름 조회 실패 시 패키지명으로 대체한다.
  이 기능을 이유로 `QUERY_ALL_PACKAGES`를 기본 요청하지 않는다

## 6. 서버로 보내는 것과 보내지 않는 것

**보낸다**: 앱별 일일·야간 집계, 구간 경계, 품질과 사유 코드, 프로필 설정.

**보내지 않는다**: 화면 내용, 알림 본문, 웹 방문 주소, 원시 Activity 이름.

OS 사용 정보 접근 권한, 분석 서버 전송 동의, 외부 AI 전송 동의는 **서로 다른 상태**로 저장한다.
접근 권한 재허용으로 전송 동의를 자동 복구하지 않는다.

## 7. FE가 직접 검증해야 하는 항목

Python은 이 항목들의 **결과 산술**만 검증한다. 실제 이벤트 동작은 실기기 확인이 필요하다.

| ID | 확인할 것 |
|---|---|
| F07 | 자정을 넘는 사용이 일별로 분리되고 야간에는 pre/after로 나뉘는가 |
| F13 | 한 앱의 Activity A/B가 겹칠 때 10분이 20분이 되지 않는가 |
| F14 | 멀티윈도우 두 앱이 각각 10분일 때 합계 20분을 물리 화면 시간이라고 표시하지 않는가 |
| F15 | 조회 실패·재부팅 상태 불명일 때 세션을 임의 연장하지 않고 partial/unavailable로 남기는가 |
| F21 | DST 전환일의 일별 구간이 23/25시간인가 |
| F22 | 잠금·화면 꺼짐 중 전경 앱 상태가 남아 있어도 사용량에서 제외하는가 |

`fixtures.json`의 `night_windows`, `daily_window_dst`, `mission_judgement`로
FE 로컬 판정이 Python 기준 구현과 같은 결과를 내는지 대조하라.
