### 부분(⚠️) 항목의 경계

- **F07 / F21** — Python은 프로필로 계산한 구간 경계와 그 위의 산술을 검증한다.
  실제 Android 이벤트가 그 경계대로 수집되는지는 실기기 확인이 필요하다.
  `contracts/fixtures.json`으로 FE 로컬 구현을 대조할 수 있다.
- **F10** — 같은 집계 키의 중복은 입력 단계에서 `ValidationError`로 막고,
  집계 경계가 프로필 계산값과 다르면 요청을 거부하며,
  같은 입력의 재호출이 같은 결과를 내는 것도 확인했다.
  로컬 저장의 upsert(누적 더하기 금지)는 BE/FE 구현이다.
- **F12 / F16** — `accepted_at_ms > window_start_ms`이면 `not_applicable`을 반환하는 것까지가 AI다.
  수락 시점 저장과 다음 미시작 구간부터의 발급은 BE 책임이다.

## 4. 누락·경계 처리 확인

| 상황 | 동작 |
|---|---|
| 전부 unavailable인 주 | `valid_days=0`, 합계 null, 미션 전부 unknown, 제안 없음 |
| partial이 섞인 주 | 주간 합계에서 제외, `per_day`에는 품질과 함께 표시, 평균은 null |
| complete + 빈 배열 | 유효 일수에 포함, 합계 0, 종료된 미션 succeeded |
| 이전 주 데이터 없음 | `comparable=false`, `reason=NO_PREVIOUS_WEEK_DATA` |
| 완전하지 않은 두 주 | `comparable=false`, `reason=INCOMPLETE_WEEK` |
| 기준선 미확보 | 해당 유형 제안 없음, `INSUFFICIENT_DATA` 설명 |
| 기준선 1분 미만 | `target_ms=null`, `LOW_USAGE_NO_TARGET` |

## 5. 목표 하한과 완화 금지

- `reduce_target(120분, 60분) = 108분`
- `reduce_target(65분, 60분) = 60분` — 최종 목표 아래로 내려가지 않는다
- `reduce_target(1분, 0) = 1분` — 반올림만으로 0이 되지 않는다
- `reduce_target(60분, 60분) = 60분` — 이미 최종 목표면 유지
- 제안은 어떤 경로에서도 현재 활성 목표보다 커지지 않는다 (F17)
- 최초 제안은 임시 목표를 상한으로 삼는다 (기준선 600분 → 제안 120분)

## 6. 날짜·시간대 경계

- 일요일 저녁 `00:00/07:00` → pre_bed `2026-09-13T23:30+09:00`, after_bed 끝 `2026-09-14T07:00+09:00`.
  이 야간은 **일요일(지난주)** 에 속한다
- `America/New_York` 3월 전환일 = 23시간, 11월 전환일 = 25시간 (각각 그 달에 정확히 하루)
- 존재하지 않는 로컬 시각(02:30) → 전환 후 첫 유효 시각(03:00)
- 중복 로컬 시각(01:30) → 먼저 오는 오프셋(EDT, UTC-4)
- 평일/주말 일정은 **밤을 시작하는 저녁의 요일**로 고른다

### 구현 중 발견해 수정한 결함

`pre_bed` 시작을 `bedtime - timedelta(30분)`으로 계산했더니 DST 갭에서 **시작이 끝보다 뒤로 갔다.**
aware datetime의 timedelta 연산은 벽시계 기준이기 때문이다.
절대 시각(밀리초)에서 빼도록 고쳤고 회귀 테스트를 남겼다.

## 7. 설명의 수치 일치

`insights[*].evidence`의 값과 `text`의 숫자가 같은 계산 결과에서 나오는지 테스트로 확인했다.
`NIGHT_TOP_APP`의 `night_total_ms`·`night_share_pct`는 `metrics.per_app`의 같은 앱 값과 일치한다.

경계 준수:
- `source`는 항상 `"template"`이며 외부 생성형 AI를 호출하지 않는다
- 확인 불가를 달성으로 설명하지 않는다 (`INSUFFICIENT_DATA` 문구에 "달성" 없음)
- 대체 사용의 원인을 확정하지 않는다 ("이유는 기록으로 알 수 없습니다")
- 통계적 유의성·중독·심리 진단 문구를 만들지 않는다
- **사용 목적의 자유 입력은 문장에 넣지 않는다.** 온보딩 고정 선택지
  (`학습/업무/여가/연락/기타`)일 때만 인용한다. 프롬프트 주입 형태의 문자열이
  설명에 실리지 않는지 테스트로 확인했다

## 8. 개인정보·보안 확인

- 라이브러리는 입력·프로필·결과를 저장하거나 외부로 보내지 않으며 로그도 남기지 않는다
- CLI 검증 실패 메시지는 **필드 위치와 오류 유형만** 출력한다.
  패키지명 등 사용자 값이 stderr/stdout에 나오지 않는 것을 테스트로 확인했다
- 잘못된 JSON은 줄·열 위치만 알리고 원문 조각을 출력하지 않는다
- 저장소의 테스트·예제 데이터는 전부 합성이다

## 9. 입증하지 않은 것

- **실제 사용자 행동 개선 효과.** 합성 데이터 테스트로 입증했다고 주장하지 않는다. 실사용 평가는 이후 단계다
- **모델 품질.** 이 패키지에는 학습 모델이 없다. 전부 규칙 기반 산술이다
- **원시 Android 이벤트의 정확성.** F13/F14/F15/F22는 실기기 검증이 필요하다
- **Python 3.12 실행.** 3.13.9에서만 확인했다
- **BE 연동 실물.** HTTP 계층·인증·DB·주간 스케줄은 구현하지 않았다
- **외부 생성형 AI 연동.** 제공자 미정이라 어댑터를 만들지 않았다. 설명 함수 경계만 분리해 뒀다
