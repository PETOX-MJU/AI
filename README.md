# 펫톡스 AI

`PETOX-MJU/AI` — 펫톡스의 모델을 **만드는** 저장소입니다.

## 저장소 경계

산출물은 전부 다른 저장소로 넘어갑니다. 여기는 과정이 사는 곳입니다.

| 저장소 | 역할 |
|---|---|
| **AI** (여기) | 모델을 **만드는** 코드 — 학습, 평가, 변환 |
| **BE** | 모델을 **서비스하는** 코드 — FastAPI, vLLM, PostgreSQL |
| **FE** | 모델을 **탑재하는** 코드 — 안드로이드 앱, TFLite 번들 |

## 구성

| 디렉터리 | 내용 | 착륙지 |
|---|---|---|
| `shorts_classifier/` | 숏폼 화면 판별 분류기 (MobileNetV3 → TFLite) | FE |
| `experiments/shorts_detection/` | 같은 문제의 VLM 베이스라인 (VARCO) | 비교용 |
| `pixelart/` | 반려동물 사진 → 픽셀 캐릭터 변환 | FE (Kotlin 이식) |
| `varco/` | 반려동물 사진 분석 프롬프트 | BE |

## 산출물 전달

`.tflite`는 git에 커밋하지 않습니다. 학습할 때마다 바이너리가 쌓여 저장소가 무거워집니다.

**GitHub Releases**로 배포하세요.

```
gh release create v0.1.0 shorts_classifier/build/shorts_classifier.tflite \
  --title "숏폼 분류기 v0.1.0" --notes "정확도 xx%, 정밀도 xx%"
```

FE는 릴리스에서 받아 `app/src/main/assets/`에 넣습니다.

## 데이터셋 주의

`datasets/`는 **절대 커밋하지 마세요.** `.gitignore`에 걸어 뒀습니다.

팀원 폰 스크린샷에는 카톡 대화, 계좌 화면, 얼굴이 섞여 들어갑니다. 공개 저장소에 올라가면
개인정보 유출입니다. 데이터셋은 팀 구글 드라이브로 공유하세요.

## 기술 선택 배경

- **분류기에 VLM이 아닌 CNN을 쓰는 이유**: 숏폼 여부는 이진 분류라 1.7B VLM이 과합니다.
  MobileNetV3는 5MB 미만·수십 ms·완전 오프라인이라 스크린샷이 기기 밖으로 나가지 않습니다.
  개인정보 문제가 원천 소멸합니다.
- **TensorFlow/Keras를 쓰는 이유**: 최종 산출물이 TFLite입니다. PyTorch→ONNX→TFLite 변환은
  실패 지점이 많고, Keras는 변환이 몇 줄로 끝납니다.
- **VARCO는 반려동물 사진 분석에만**: 사용자가 자기 사진을 직접 올리는 경로라 동의 구조가
  명확하고 서버 전송이 정당화됩니다. 화면 캡처와는 성격이 다릅니다.
