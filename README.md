# 펫톡스 AI

`PETOX-MJU/AI` — 펫톡스의 모델을 **만드는** 저장소입니다.

## 저장소 경계

산출물은 전부 다른 저장소로 넘어갑니다. 여기는 과정이 사는 곳입니다.

| 저장소 | 역할 |
|---|---|
| **AI** (여기) | 모델을 **만드는** 코드 — 학습, 평가, 변환 |
| **BE** | 모델을 **서비스하는** 코드 — FastAPI, vLLM, PostgreSQL |
| **FE** | 모델을 **탑재하는** 코드 — 안드로이드 앱, TFLite 번들 |

## 구성

| 디렉터리 | 내용 | 착륙지 |
|---|---|---|
| `shorts_classifier/` | 숏폼 화면 판별 분류기 (MobileNetV3 → TFLite) | FE |
| `experiments/shorts_detection/` | 같은 문제의 VLM 베이스라인 (VARCO, 평가 전용) | 비교용 |
| `pixelart/` | 반려동물 사진 → 픽셀 캐릭터 변환 | FE (Kotlin 이식) |
| `pet_analysis/` | 반려동물 사진 분석 (VLM, 교체 가능) | BE |

## 산출물 전달

`.tflite`는 git에 커밋하지 않습니다. 학습할 때마다 바이너리가 쌓여 저장소가 무거워집니다.

**GitHub Releases**로 배포하세요.

```
gh release create v0.1.0 shorts_classifier/build/shorts_classifier.tflite \
  --title "숏폼 분류기 v0.1.0" --notes "정확도 xx%, 정밀도 xx%"
```

FE는 릴리스에서 받아 `app/src/main/assets/`에 넣습니다.

## 데이터셋 주의

`datasets/`는 **절대 커밋하지 마세요.** `.gitignore`에 걸어 뒀습니다.

팀원 폰 스크린샷에는 카톡 대화, 계좌 화면, 얼굴이 섞여 들어갑니다. 공개 저장소에 올라가면
개인정보 유출입니다. 데이터셋은 팀 구글 드라이브로 공유하세요.

## 캡처 제약 (필수)

화면 캡처는 **사용자 본인 화면을 본인 동의로** 찍는 것이라 그 자체는 문제없다.
쟁점은 캡처한 것을 어떻게 다루느냐다. 아래는 지켜야 하는 설계 요구사항이지 권고가 아니다.

### 1. 대상 앱 화이트리스트

**유튜브·인스타그램·틱톡이 포그라운드일 때만 캡처한다.** 다른 앱으로 전환되면 캡처를
즉시 중단한다. 카카오톡·뱅킹·메모 화면은 애초에 찍히지 않아야 한다.

```
foregroundPackage in TARGET_PACKAGES  →  캡처 진행
그 외                                  →  캡처 중단
```

법적 리스크를 엔지니어링 제약으로 바꾸는 가장 확실한 방법이다.
**나중에 붙이면 빠뜨리기 쉬우니 스파이크 단계부터 넣어라.**

### 2. 프레임은 메모리에서만

디스크 저장 금지, 서버 전송 금지, 판별 직후 폐기. 온디바이스 CNN을 택한 이유가 이것이다.

### 3. 데이터셋은 비공개

`.gitignore` 처리돼 있다. 팀 외부 배포 금지, 대회 종료 후 폐기.

TDM(정보분석) 면책 조항은 국내에서 **아직 입법되지 않았다.** 비영리 교육·연구 목적에
데이터셋 비공개라는 조건에서 공정이용(저작권법 제35조의5)에 기대는 구조이므로,
이 조건이 깨지면 근거가 사라진다.

### 4. 앱 내 고지

화면 캡처를 사용한다는 사실과 "기기 외부로 전송하지 않음"을 사용자에게 명시한다.

### 5. 미성년자 동의

계획서 타깃에 청소년이 포함된다. **만 14세 미만은 법정대리인 동의가 필수**다.

> 상용 출시로 가면 학습 데이터셋 저작권이 별도 검토 대상이다 (「상용 배포 체크리스트」 참고).
> 대회 범위에서는 위 5가지로 충분하다.

## 기술 선택 배경

- **분류기에 VLM이 아닌 CNN을 쓰는 이유**: 숏폼 여부는 이진 분류라 1.7B VLM이 과합니다.
  MobileNetV3는 5MB 미만·수십 ms·완전 오프라인이라 스크린샷이 기기 밖으로 나가지 않습니다.
  개인정보 문제가 원천 소멸합니다.
- **TensorFlow/Keras를 쓰는 이유**: 최종 산출물이 TFLite입니다. PyTorch→ONNX→TFLite 변환은
  실패 지점이 많고, Keras는 변환이 몇 줄로 끝납니다.
- **VLM은 반려동물 사진 분석에만**: 사용자가 자기 사진을 직접 올리는 경로라 동의 구조가
  명확하고 서버 전송이 정당화됩니다. 화면 캡처와는 성격이 다릅니다.
- **Qwen2.5-VL(Apache 2.0)을 쓰는 이유**: 상용 배포가 목표라 조건 없는 라이선스를 택했습니다.
  열거값을 영어로 받고 코드에서 한국어로 옮겨, 모델의 한국어 능력에 묶이지 않게 했습니다.

VARCO는 비상업 라이선스라 **Qwen2.5-VL(Apache 2.0)로 교체했습니다.** 대회 단계에서는 VARCO도
문제없었지만, 나중에 바꾸면 프롬프트를 다시 튜닝해야 해서 미리 정리했습니다.

> **보도자료가 아니라 모델 카드를 보세요.** 카카오 Kanana는 보도자료에 Apache 2.0으로
> 나오지만 그건 텍스트 LLM 기준이고, VLM 변형은 `kanana` 자체 라이선스에 상업 조건이
> 불명확합니다. Qwen도 2026년 8월 이후 모델별로 갈립니다. 같은 제품군 안에서도
> 변형마다 다르니 **배포 직전에 쓰려는 그 모델의 카드를 확인하세요.**

### 남은 최대 쟁점: 학습 데이터셋

`shorts_classifier/` 데이터셋은 유튜브·틱톡 화면 스크린샷입니다. 타사 UI와 저작물 영상
프레임이 담기는데, **TDM(정보분석) 면책 조항이 국내에서 아직 입법되지 않았습니다.**
공정이용(저작권법 제35조의5) 판단에 기대는 구조입니다.

- 비영리 교육·연구 + 데이터셋 비공개 → 대회 범위에서는 사실상 문제없음
- **상용 서비스 학습 데이터 → 안전장치 없음. 자문 필요**

노출을 줄이는 방법:
- 데이터셋을 끝까지 비공개로 유지 (배포·공개 금지)
- 팀이 직접 제작한 영상을 각 앱에 올려 촬영하면 원저작물 문제가 사라진다 (품은 들지만 확실)
- 학습된 가중치는 원본 이미지를 재현하지 않는다 — 다만 이것만으로 면책되지는 않는다

**모델을 바꾼다고 이 문제가 해결되지는 않습니다.** 상용화 시점에 반드시 별도로 다루세요.
