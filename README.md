# 펫톡스 AI

`PETOX-MJU/AI` — 펫톡스의 모델을 **만드는** 저장소.

**상용 배포를 전제로 설계했다.** 라이선스가 걸리는 구성요소는 제품 경로에 넣지 않고,
추론은 전부 온디바이스로 돌린다.

## 설계 원칙

1. **온디바이스 우선.** 서버 추론은 GPU 상시 비용이다. 무료 앱에서 감당이 안 된다.
2. **서버는 선택사항.** 서버가 죽어도 앱의 모든 핵심 기능이 동작해야 한다.
3. **전용 소형 모델 > 범용 대형 모델.** 더 작고, 더 정확하고, 라이선스가 깨끗하다.
4. **개인정보는 기기를 벗어나지 않는다.** 화면 프레임도, 반려동물 사진도.
5. **모델 카드를 직접 확인한다.** 보도자료는 근거가 아니다.

## 아키텍처

```
[안드로이드 앱 / Kotlin]  ─ 전부 온디바이스
 ├ 오버레이 서비스 (WindowManager)
 ├ 앱 감지 (UsageStatsManager) + 대상 앱 화이트리스트
 ├ 화면 캡처 → shorts_classifier.tflite      숏폼 판별
 ├ 반려동물 사진 → ML Kit Segmentation
 │                → pet_classifier.tflite     종·털길이
 │                → 팔레트 분석               털색
 │                → 이름 테이블               이름 추천
 ├ 픽셀화 (Bitmap 연산)
 └ Room  ─ 사용 로그·코인·캐릭터 성장 (진실의 원천)

[서버 / 선택]  ─ 없어도 앱이 완전히 동작한다
 └ FastAPI + PostgreSQL ─ 계정 동기화·백업만
```

**모델 추론이 서버에 하나도 없다.** GPU 비용 0, 개인정보 전송 0, 오프라인 동작.

## 저장소 경계

| 저장소 | 역할 |
|---|---|
| **AI** (여기) | 모델을 **만드는** 코드 — 학습, 평가, 변환 |
| **BE** | 계정 동기화·백업 — FastAPI, PostgreSQL |
| **FE** | 모델을 **탑재하는** 코드 — 안드로이드 앱, TFLite 번들 |

## 구성

| 디렉터리 | 내용 | 착륙지 |
|---|---|---|
| `shorts_classifier/` | 숏폼 화면 판별 (MobileNetV3 → TFLite) | FE |
| `pet_classifier/` | 종·털길이 분류 + 색 추출 + 이름 추천 | FE |
| `pixelart/` | 반려동물 사진 → 픽셀 캐릭터 변환 | FE (Kotlin 이식) |
| `experiments/` | VLM 베이스라인 — **제품 경로 아님** | 비교용 |

`experiments/` 의 모델은 성능 비교 기준선일 뿐이다. **배포 대상이 아니다.**

## 라이선스

전 구성요소 대장은 **[LICENSING.md](LICENSING.md)** 에 있다. 배포 전 반드시 재검증하라.

요약: 제품 경로에 라이선스 걸림돌은 없다. 남은 회색지대는 ImageNet 사전학습 가중치
하나이며 자문 항목으로 기록해 뒀다.

## 데이터 전략

**TDM(정보분석) 면책 조항은 국내에서 아직 입법되지 않았다.** 타사 앱 화면을 긁어
학습시키면 공정이용 판단에 기대야 하고, 상용 서비스에는 안전장치가 없다.

**해법: 우리가 만든 영상을 우리가 촬영한다.** 팀이 제작한 짧은 영상을 각 앱에 올리고
그 화면을 촬영한다. 분류기가 학습하는 건 영상 내용이 아니라 UI 배치(오른쪽 세로 버튼 열,
하단 캡션 바)라서 자체 콘텐츠로 바꿔도 정확도 손실이 없다.

반려동물 사진은 팀·지인 것으로 모은다. 촬영자 동의만 받으면 저작권 쟁점이 없다.

`datasets/` 는 **절대 커밋하지 마라.** `.gitignore` 처리돼 있다.

## 캡처 제약 (필수)

화면 캡처는 사용자 본인 화면을 본인 동의로 찍는 것이라 그 자체는 문제없다.
쟁점은 캡처한 것을 어떻게 다루느냐다. 아래는 설계 요구사항이지 권고가 아니다.

### 1. 대상 앱 화이트리스트

**유튜브·인스타그램·틱톡이 포그라운드일 때만 캡처한다.** 다른 앱으로 전환되면 즉시 중단.
카카오톡·뱅킹·메모 화면은 애초에 찍히지 않아야 한다.

```
foregroundPackage in TARGET_PACKAGES  →  캡처 진행
그 외                                  →  캡처 중단
```

법적 리스크를 엔지니어링 제약으로 바꾸는 가장 확실한 방법이다.
**나중에 붙이면 빠뜨리기 쉬우니 스파이크 단계부터 넣어라.**

### 2. 프레임은 메모리에서만
디스크 저장 금지, 서버 전송 금지, 판별 직후 폐기.

### 3. 데이터셋 비공개
팀 외부 배포 금지.

### 4. 앱 내 고지
화면 캡처 사용 사실과 "기기 외부로 전송하지 않음"을 명시한다.

### 5. 미성년자 동의
**만 14세 미만은 법정대리인 동의가 필수.**

## 산출물 전달

`.tflite` 는 git 에 커밋하지 않는다. GitHub Releases 로 배포한다.

```
gh release create v0.1.0 shorts_classifier/build/shorts_classifier.tflite \
                         pet_classifier/build/pet_classifier.tflite \
  --title "모델 v0.1.0" --notes "숏폼 정밀도 xx% / 종 판별 정확도 xx%"
```

FE 는 릴리스에서 받아 `app/src/main/assets/` 에 넣는다.
